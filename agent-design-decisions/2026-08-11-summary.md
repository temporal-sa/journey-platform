# 2026-08-11 Experiment Analytics & Auto-Registration Architecture Summary

## Executive Overview

This release addresses the Experiment Analytics reporting pipeline, adding automatic registration of experiment nodes from journey drafts, a multi-experiment selector UI, and backend aggregate report materialization.

---

## 1. Frontend Multi-Experiment Selector (`ExperimentReportView.tsx`)

- **Auto-Discovery of Workspace Experiments**: Added a query for `apiClient.listExperiments()` when mounting `ExperimentReportView`.
- **Dropdown Selector Component**: Integrated an experiment selector `<select>` element (`[data-testid="experiment-selector-dropdown"]`) into the dashboard header bar, allowing users to switch between experiments in the workspace.
- **Dynamic Resolution & Fallback**: The active experiment automatically resolves to:
  1. User-selected experiment ID from dropdown state
  2. Explicit `experimentId` prop or URL parameter
  3. First available registered experiment in the database
- **Non-Zero Metrics Presentation**: Computes and displays aggregate metrics (`Assigned`, `Exposed`, `Attempted`, `Accepted`, `Delivered`, `Unique Opens`, `Unique Clicks`, `Conversions`, `Conversion Rate`, `Max Lift %`) alongside the Sample Ratio Mismatch (SRM) status card and variant breakdown table.

---

## 2. Backend Auto-Registration & Journey Sync (`journey.go` & `webmcp.go`)

- **Automatic Draft Node Scanning (`syncDraftExperiments`)**:
  - When journey drafts are created or updated via REST API (`POST/PUT /api/v1/journeys/drafts`) or WebMCP (`create_journey_draft`), the handler scans draft nodes for `type: "Experiment"`, `"ab_test"`, `"split"`, or `"multivariate"`.
- **Definition Generation**:
  - Extracts variant keys, names, and basis-point weights (or defaults to a 50/50 Control / Treatment split).
  - Computes a deterministic SHA-256 `ContentHash` over the variant configuration.
  - Automatically registers or updates the experiment definition in PostgreSQL (`experiment_definitions` table).

---

## 3. Backend Experiment Report Materialization (`public_api.go` & `store/postgres`)

- **Repository Query Methods**:
  - Added `ListAssignmentsByExperiment(ctx, tenantID, expID)` and `ListExposuresByExperiment(ctx, tenantID, expID)` to the `Repository` interface and implemented them in `PostgresRepository` and `MemoryRepository`.
- **Report Handler (`GetExperimentReport`)**:
  - Updated `/api/v1/reports/experiments/{id}` and `/api/v1/reports/aggregate` endpoints to aggregate assignment and exposure facts for each variant.
  - Returns `variant_metrics` array and SRM status in the `AggregateReport` JSON payload matching frontend expectations.

---

## 4. Experiment Versioning & Immutable Hashes (`experiments.go`)

- **Stable Identity**: Draft updates retain the stable `experiment_id` assigned to the node.
- **Content Hash Validation**: Modifying variant weights or adding new variants changes the `ContentHash`, triggering an automatic version increment (`Version N -> Version N+1`).
- **Data Isolation**: Historical exposure facts remain tied to previous versions, preventing metric corruption across draft revisions.

## 7. OpenTelemetry W3C Tracing & Jaeger Database Span Correlation (\`main.go\` & \`traced_db.go\`)

- **Chi Middleware Integration (\`cmd/control-api/main.go\` & \`internal/api/middleware/logging.go\`)**:
  - Wired \`appMiddleware.RequestID\` and \`appMiddleware.RequestLogger\` into the \`control-api\` Chi router to export W3C OpenTelemetry HTTP spans (\`HTTP GET/POST/PUT/DELETE\`) to Jaeger OTLP (\`http://127.0.0.1:4318/v1/traces\`).
  - Implemented payload capture for \`POST\`, \`PUT\`, and \`PATCH\` requests (safely truncated at 8KB) under \`http.request.payload\` span attributes.
- **Nested Database Query Child Spans (\`traced_db.go\`)**:
  - Created \`postgres.TracedDB\` wrapper (\`internal/store/postgres/traced_db.go\`) for the \`DBTX\` interface.
  - Automatically correlates database query execution (\`DB SELECT\`, \`DB INSERT\`, \`DB UPDATE\`, \`DB DELETE\`) as child spans (\`CHILD_OF\`) under the parent HTTP request span in Jaeger.
- **PostgreSQL Array Scan & Unique Constraint Error Handling**:
  - Wrapped \`c.Tags\` with \`pq.Array(...)\` in \`PostgresRepository\` queries and scans to eliminate PostgreSQL \`TEXT[]\` array scan errors.
  - Wrapped primary key / unique constraint errors (\`code 23505\`) with \`postgres.ErrAlreadyExists\` for clean API upsert handling.
  - Appended unique 6-character hashes to auto-generated catalog IDs (\`CatalogCreationModal.tsx\`) to prevent collisions.
