# 2026-08-14 Runtime Behavior Injection, Tracing & UI Refinements Architecture Summary

## Executive Overview

This release delivers major architectural enhancements across the runtime execution engine, telemetry pipeline, and developer experience. Highlights include extracting a dedicated in-memory `BehaviorInjector` component for dynamic activity failure and latency injection, full OpenTelemetry Jaeger trace span exports for Temporal workflows and Kafka records, unified Zerolog wiring across Temporal workers, automatic Temporal Search Attribute registration, WebMCP workflow authoring, and a complete visual redesign of the Condition Node Rule Builder.

---

## 1. Dedicated In-Memory Behavior & Fault Injection Architecture (`internal/activities/behavior.go`)

- **Decoupled from Workflow Input**:
  - Replaced the legacy approach of passing simulation settings via immutable workflow start parameters (`simulated_activity_failure`, `max_failure_attempts`) with a dedicated in-memory interceptor component (`BehaviorInjector`).
  - Removed `max_failure_attempts` and attempt-counter tracking in favor of a real-time binary toggle and dynamic latency management.
- **`ActivityBehavior` Interface**:
  - Implemented an extensible contract for activity interceptors:
    ```go
    type ActivityBehavior interface {
        Match(info ActivityInfo) bool
        Execute(ctx context.Context, info ActivityInfo) error
    }
    ```
- **Supported Runtime Behaviors**:
  - **`ErrorBehavior`**: Injects simulated execution errors globally or targeted by `ActivityName` and/or `NodeID`.
  - **`DelayBehavior`**: Injects arbitrary simulated latency/sleep with context cancellation awareness.
  - **`HookBehavior`**: Executes custom callbacks `func(ctx context.Context, info ActivityInfo) error` for runtime inspection and side effects.
- **Universal Activity Interception**:
  - Every activity entry point (`ExecuteActionGateway`, `ExecuteNode`, `EvaluateCondition`, `LoadCompiledIR`, `EmitLifecycleEvent`, `CreateSubscription`, `CloseSubscription`, `GetOrAssign`, `RecordExposure`, `ExposeAssignment`, `EmitOutcome`, `ResolveAttributes`, `ResolveParameters`, `EvaluatePolicy`) calls `a.getBehaviorInjector().Intercept(ctx, info)`.
- **Daemon Worker Synchronization**:
  - Added a background polling loop (250ms interval) in `cmd/journey-worker/main.go` that synchronizes in-memory failure and latency settings from `control-api` in real time.

## 2. Activity Latency Injection & REST Endpoints (`internal/api/handlers/simulation.go`)

- **Endpoints Added & Updated**:
  - **`GET /api/v1/simulation/activity-latency`**: Returns current activity latency in milliseconds (`{ "latency_ms": 250 }`).
  - **`POST /api/v1/simulation/activity-latency`**: Dynamically updates the activity latency in memory.
  - **`GET /api/v1/simulation/activity-failure`**: Unified simulation endpoint returning both failure mode and latency (`{ "simulated_activity_failure": false, "latency_ms": 250 }`).
- **Developer Tools UI (`DeveloperPanel.tsx`)**:
  - Added an **Activity Latency Simulation** card (`activity-latency-simulation-card`).
  - Displays real-time status badges (`0 ms (NO LATENCY)` vs `250 ms LATENCY (ACTIVE)`).
  - Provided numeric input field for milliseconds with instant presets (`0ms`, `100ms`, `250ms`, `500ms`, `1000ms`, `2000ms`) and a `Reset (0ms)` button.

## 3. Centralized OpenTelemetry Tracing & Jaeger Exports (`internal/telemetry/tracing/`)

- **Global OTel TracerProvider (`tracing.InitTracerProvider`)**:
  - Created `internal/telemetry/tracing/tracer.go` registering a global `sdktrace.TracerProvider` with `otlptracehttp` exporting to Jaeger OTLP HTTP (`http://127.0.0.1:4318/v1/traces`).
  - Configured batch span processing and global W3C context propagators (`TraceContext` & `Baggage`).
- **Temporal OTel Interceptor Activation**:
  - Activated `opentelemetry.NewTracingInterceptor` across `journey-worker`, `control-api`, and `event-ingress`, enabling full capture of Temporal workflow spans (`StartWorkflow`, `ExecuteWorkflow`) and activity spans (`RunActivity:ExecuteActionGateway`, `RunActivity:LoadCompiledIR`, etc.) in Jaeger.
- **Kafka Message Span Instrumentation**:
  - Added `kafka.consume` and `kafka.produce` span creation with topic, partition, offset, and key attributes in `internal/ingress/capture.go`, `internal/ingress/dispatch.go`, and `internal/outcomes/consumer.go`.
- **Daemon & API Registration**:
  - Registered tracer provider across `journey-worker`, `control-api`, `event-ingress`, `outcome-ingress`, `target-dispatcher`, and `report-materializer`.

## 4. Unified Zerolog Wiring for Temporal Loggers (`temporal_adapter.go`)

- **Adapter Implementation**:
  - Built `temporalZerologAdapter` implementing `go.temporal.io/sdk/log.Logger` (`Debug`, `Info`, `Warn`, `Error`).
  - Converts Temporal SDK key-value pairs into structured Zerolog fields, extracting native `error` instances and routing output to both `os.Stdout` (pretty console in dev mode) and the `LogBuffer` ring sink.
- **Client & Worker Wiring**:
  - Configured `client.Options{ Logger: logging.NewTemporalLogger() }` across `cmd/journey-worker/main.go`, `cmd/control-api/main.go`, `cmd/event-ingress/main.go`, `internal/workflows/worker.go`, and `internal/api/handlers/handlers.go`.
- **Deterministic Replay Safety**:
  - `workflow.GetLogger(ctx)` retains Temporal's replay suppression while routing live execution logs into Zerolog and the Live Log Stream modal.

## 6. Temporal Search Attributes Auto-Registration (`init-temporal-search-attributes.sh`)

- **Search Attributes Registered**:
  - **`JourneyName`** (`Keyword`): Human-readable name of the journey draft.
  - **`IsStaticList`** (`Bool`): Identifies if execution originated from a static audience list.
  - **`StaticListID`** (`Keyword`): Identifier of the static list used to start the workflow.
  - **`InternalWorkflowID`** (`Keyword`): Workflow execution key.
- **Portability & Boot Verification**:
  - Converted `scripts/init-temporal-search-attributes.sh` to portable `/bin/sh` syntax compatible with minimal Alpine containers (`temporalio/admin-tools`) and host environments.
  - Configured `compose.yaml` (`temporal-init` container) and `scripts/dev.sh` to register attributes idempotently on cluster boot.
- **Workflow Start Integration**:
  - `internal/api/handlers/public_api.go` and `internal/ingress/dispatch.go` populate search attributes in `StartWorkflowOptions` and `CompiledJourneyInput`.
  - Workflow execution automatically invokes `workflow.UpsertSearchAttributes(ctx, sa)` on start.
