# Agent Design Decisions & Canvas Refactoring Summary (2026-08-04)

This document records all UX/UI design decisions, handle connection fixes, non-crossing auto-arrange layout algorithms, unified node selection glow lighting, node palette synchronization, and read-only canvas lock enforcement implemented on **August 4, 2026**.

---

## 1. Handle Connection Attachment & Alignment (`web/src/components/editor/nodes/`)

- **Root Cause**: React Flow calculates edge connection paths using DOM handle coordinates (`y = 0` / `y = 112px`). Overriding handle positions with Tailwind `-top-4` (`top: -16px`) and `-bottom-4` (`bottom: -16px`) shifted the visual handle circle away from the edge path anchor point, creating a visible gap between edges and handles.
- **Resolution**: Removed `-top-4` and `-bottom-4` class overrides across all 11 node components (`EventStartNode`, `EmailNode`, `SMSNode`, `PushNode`, `InAppNode`, `WebhookNode`, `ConditionNode`, `DelayNode`, `WaitForEventNode`, `ExperimentNode`, `ExitNode`). Edges now touch handle circles perfectly without offset.

---

## 2. Non-Crossing Auto-Arrange Layout Algorithm (`web/src/stores/editorStore.ts`)

- **Branch Handle Ranking**: Implemented `sortLevelNodesByBranchHandles` helper function within `autoArrangeVertical` and `autoArrangeHorizontal` in `editorStore.ts`.
- **Rank Assignments**:
  - `True`, `variant_a`, `event`, `yes` handles -> **Rank 0 (Left)**
  - `False`, `variant_b`, `timeout`, `no` handles -> **Rank 2 (Right)**
- **Result**: Target nodes for decision branches are sorted deterministically left-to-right based on their incoming handle rank. Edges from `True` (Left) and `False` (Right) branches no longer cross.

---

## 3. Unified Selection Glow Lighting (`web/src/components/editor/nodes/`)

- **CSS Specificity Fix**: Resolved a CSS specificity collision in Tailwind CSS build output where `.glass-panel` (`border: 1px solid rgba(255, 255, 255, 0.1)`) overrode standard Tailwind utility border classes (`border-amber-400`, `border-rose-400`, `border-[#4cd7f6]`) on non-action nodes.
- **Dynamic Inline Style Overrides**: Applied dynamic inline style overrides (`style={{ ...(selected ? { borderColor: themeHex, backgroundColor: themeHexAlpha } : {}) }}`) across all 11 node components when `selected: true`.
- **Result**: Selecting any node (Trigger, Action, Decision, or Utility) instantly lights up the card with a signature theme border and background glow.

## 5. Read-Only Canvas Lock Enforcement (`web/src/stores/editorStore.ts`, `Canvas.tsx`, `Palette.tsx`, `NodeInspector.tsx`)

- **Centralized Store Lock State**: Promoted `isCanvasLocked` to Zustand `editorStore.ts` with `toggleCanvasLock()` and `setIsCanvasLocked()`.
- **Store Mutation Guards**: Added `if (get().isCanvasLocked) return;` to all 11 graph-modifying store actions (`addNode`, `updateNodes`, `updateEdges`, `addEdge`, `deleteElements`, `undo`, `redo`, `autoArrangeHorizontal`, `autoArrangeVertical`, `updateInspectorEdit`, `commitInspectorEdits`).
- **Canvas & Component Controls**:
  - Disabled node dragging, connectability, element selection, node focus, and edge focus in React Flow when `isCanvasLocked` is true.
  - Guarded `onDrop`, `onDragOver`, `onConnect`, `onReconnect`, and `handleAddNodeFromPalette`.
  - Palette items render disabled (`opacity-40 pointer-events-none`) with a `"Canvas is locked (Read Only)"` tooltip when locked.
  - Node Inspector displays a `🔒 Canvas is Locked (Read Only)` warning banner and disables Save/Edit buttons.
